# SAP GUI: Logon & configuration

Day 3 moves from the web to the desktop. Modules 1 to 6 automated **SAP S/4HANA Fiori** in a browser; today you automate the **classic SAP GUI (SAP WinGUI)** through **SAP Logon**. The two look different and are set up differently, so the day starts with configuration, then builds the automation in three small workflows.

!!! warning "You need an SAP environment for this day"
    As noted in [Setup](../getting-started/setup.md), UiPath cannot provide an SAP system; access is a separate SAP license. Use your organization's sandbox SAP system for this day. If you have none, follow along on the recording and apply the same patterns later.

## SAP GUI vs Fiori

| | SAP S/4HANA Fiori (Module 3) | SAP GUI / WinGUI (Day 3) |
|---|---|---|
| Runs in | A browser | A desktop app, opened from **SAP Logon** |
| Built on | SAPUI5 (web) | Classic SAP controls |
| Setup to automate | None beyond browser automation | **SAP GUI Scripting** must be enabled |
| If scripting is off | n/a | Fall back to Computer Vision / image / OCR |

## Enable SAP GUI Scripting (client side)

The desktop GUI exposes reliable selectors to the robot **only when SAP GUI Scripting is enabled**. It has a server side and a client side. The **server side** (transaction `RZ11`, parameter `sapgui/user_scripting = TRUE`) is your SAP administrator's job. Today you do the **client side only**.

!!! info "Enabling scripting is not a security risk"
    From the SAP server's point of view there is no difference between GUI traffic generated by a script and traffic generated by a person. A script runs with exactly the same rights and the same data-validation rules as the user who started it. Turning scripting off just forces developers onto image and OCR automation; the robot can still do the same things unattended, so there is nothing gained by making it harder.

**Client-side steps** (do these on your machine):

1. Start **SAP Logon**.
2. Open the **Options** menu from the main SAP Logon window.
3. Go to **Accessibility & Scripting → Scripting**.
4. Check **Enable scripting**.
5. Uncheck **Notify when a script attaches to SAP GUI** and **Notify when a script opens a connection** (so pop-ups don't block the robot).
6. Click **OK** to save.
7. Recommended: make sure the connection uses **High Speed Connection (LAN)** so SAP sends the full UI your selectors expect. To check:
    1. In **SAP Logon**, right-click your connection (the **SAP Testing app** entry) and choose **Properties**.
    2. Open the **Network** tab (or **Advanced** / **Connection**, depending on your SAP GUI version).
    3. Make sure **Low Speed Connection** is **unchecked**. Unchecked means high speed (LAN), which is the normal full-UI mode and the default.
    4. Click **OK**.

!!! tip "Quick check without extra SAP rights"
    Click **Customize Local Layout** (the coloured monitor icon on the SAP toolbar, `Alt+F12`) and look for **Script Recording and Playback**. If it is greyed out or missing, scripting is not enabled.

The full reference, including the server-side steps, is in the UiPath documentation: [SAP WinGUI configuration steps](https://docs.uipath.com/activities/other/latest/ui-automation/sap-wingui-configuration-steps).

## Add a connection in SAP Logon

Create the connection the workflows will open:

1. Start **SAP Logon**.
2. Choose **Add new connection**.
3. Click **Next**.
4. Enter the connection data:

    | Field | Value |
    |-------|-------|
    | Connection type | **Custom Application Server** |
    | Description | **SAP Testing app** |
    | System ID | *your system ID* |
    | Instance Number | **00** |
    | Application Server | *your server* |

5. Finish and save. The **SAP Testing app** connection now appears in SAP Logon; double-clicking it opens the logon screen.
